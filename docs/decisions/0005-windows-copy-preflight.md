# 0005 — Windows-copy preflight, capture space and recovery

Status: implemented; privileged VHD execution and boot proofs remain deferred under the non-admin goal.

The source-content choices and privileged worker share pure `WindowsCopyOptions` and `WindowsCopyPlanning` logic. Exclusions are literal, normalized relative paths: roots, traversal, wildcard patterns and control characters are rejected. Required Windows, Microsoft shared/profile branches and their ancestors cannot be excluded. Registry install locations are hints for splitting optional content, never authority to omit required branches.

The preview runs unelevated. Unreadable classification branches are retained in full. Incomplete sizes and links/cloud content are identified explicitly. The privileged workflow validates disk fingerprints, virtual-only mode, destination protections, typed confirmation and source NTFS membership, then creates a snapshot and measures selected content before clearing the destination. Every platform stage releases its resources on failure; fake-platform tests exercise the same orchestration without VHDs or privileged commands.

The capture image resides temporarily on the destination while DISM applies it. Capacity preflight therefore conservatively allows twice the selected logical file bytes plus at least 64 MiB of working space (or 10% of selected bytes). It does not assume compression or hard-link savings. A destination that could hold only the final copy may be refused; the preview explains temporary-image space. External staging is not implemented.

The layout includes recovery space after Windows in GPT and MBR layouts. ADR 0008 extends the initial 1 GiB reserve to account for the measured image and servicing space, prepares GPT attributes and destination activation instructions, and uses a 300 MiB EFI minimum. A readable source `Winre.wim` is copied and registered against the offline destination with an explicit `/target`; otherwise the worker reports unregistered recovery space. Actual attribute persistence, activation and Windows boot still need elevated/VM verification. No live-system recovery configuration is changed by the implementation's command arguments.

DISM capture/apply request integrity checking, verification and extended-attribute preservation. The exclusion list is anchored to the source root. BIOS boot-sector preparation always names the destination letter; tool availability is checked before erasure. No Windows-copy/boot command was executed while developing this change.
