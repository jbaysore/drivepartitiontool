# ADR 0007: reversible integration and an unelevated portable package

Status: accepted for the non-admin phase; live Shell/service integration remains owner verification.

The folder-handler setting uses a private `DrivePartitionTool.Open` verb under the per-user Folder, Directory and Drive classes and selects that verb as the class default. This replaces the plan's literal `shell\open` override: built-in open commands remain intact, and typed backups preserve the previous default (including an absent value). Backups are complete before defaults change. Restore removes only matching app-owned fragments and preserves later external changes. Construction, startup and opening Settings are read-only; only an explicit setting/restore action changes live registration. Tests use GUID-named registry trees under `Software\DrivePartitionTool.Tests`.

File/disk jobs hold the process open when its window closes. A shutdown barrier prevents a new job racing with exit. Rule timers/watchers and service subscriptions are disposed. Unexpected startup/dispatcher failures write a standalone report and exit; reports fall back to a temporary directory when the normal log location cannot be written. Test-app teardown checks an idle job state and a normal exit, and fails if cleanup needs to kill its own process.

`publish.ps1` produces a unique, self-contained Windows x64 folder, with separate self-contained service and worker subfolders. It preserves existing packages, records source identity and payload hashes, and verifies runtimes, PE architecture and privilege manifests without starting privileged executables. The app/service remain `asInvoker`; the worker remains `requireAdministrator`. Packaging never installs a service or changes Shell/taskbar settings. This intentionally separates the implementation plan's publish and install actions to support the authorized no-admin goal. The guide documents explicit owner-present install/upgrade steps. Existing locked destination files are checked before copying an upgrade; failures are reported rather than silently skipping files.

Evidence: the full non-admin suite passed 251 tests with zero build warnings/errors (`.local/m10-full-tests.log`). The final UI harness revision passed all 21 UI tests with normal-exit checks (`.local/m10-shutdown-ui-tests.log`). An initial package passed hash/runtime/manifest verification and the packaged UI suite; a final package from committed source is recorded separately in `PROGRESS.md`. No live folder defaults, service registration, VHD or boot files were changed. Performance and the remaining clone/recovery work are tracked in `NON_ADMIN_AUDIT.md`.
